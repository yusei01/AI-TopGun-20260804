# ユーザーストーリー 生成プラン

## 採用方針

- **ストーリー分割アプローチ**: ユーザージャーニーベース（購入体験の流れに沿って整理）
- **ストーリー粒度**: エピック → ユーザーストーリー（2階層）
- **フォーマット**: 標準フォーマット「〜として、〜したい。なぜなら〜だから。」+ 受け入れ基準
- **INVEST基準**: 各ストーリーが Independent / Negotiable / Valuable / Estimable / Small / Testable を満たす
- **ペルソナ**: 3種類（ゲスト購入者・会員ユーザー・サイト管理者）

---

## 生成ステップ（チェックリスト）

### PART 1: ペルソナ定義
- [x] ペルソナ1: ゲスト購入者（初回訪問・アカウントなし）を定義する
- [x] ペルソナ2: 会員ユーザー（リピーター・アカウントあり）を定義する
- [x] ペルソナ3: サイト管理者（オーナー・バックオフィス担当）を定義する
- [x] 各ペルソナのゴール・課題・行動パターンを記述する
- [x] personas.md として保存する

### PART 2: エピック定義
- [x] EPIC-01: 商品を探す（カタログ閲覧・検索）
- [x] EPIC-02: 商品を購入する（2ステップ購入フロー）
- [x] EPIC-03: デジタルコンテンツを受け取る（ダウンロード・ライセンス配信）
- [x] EPIC-04: アカウントを管理する（任意登録・ログイン・履歴確認）
- [x] EPIC-05: サイトを管理する（管理画面・商品/注文/顧客管理）

### PART 3: ユーザーストーリー生成
- [x] EPIC-01 配下のストーリーを生成する（商品一覧・詳細・検索）
- [x] EPIC-02 配下のストーリーを生成する（購入フロー・決済・完了）
- [x] EPIC-03 配下のストーリーを生成する（ダウンロード・ライセンス配信・メール通知）
- [x] EPIC-04 配下のストーリーを生成する（アカウント登録・ログイン・マイページ・パスワードリセット）
- [x] EPIC-05 配下のストーリーを生成する（商品管理・注文管理・顧客管理）
- [x] 各ストーリーに受け入れ基準（Acceptance Criteria）を記述する
- [x] 各ストーリーをペルソナにマッピングする
- [x] stories.md として保存する

### PART 4: 検証
- [x] 全ストーリーが INVEST 基準を満たすか確認する
- [x] 要件定義書（requirements.md）との整合性を確認する
- [x] ペルソナとストーリーのマッピングが網羅的か確認する
