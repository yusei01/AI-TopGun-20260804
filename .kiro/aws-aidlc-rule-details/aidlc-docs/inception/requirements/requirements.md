# 要件定義書

## インテント分析サマリー

| 項目 | 内容 |
|---|---|
| ユーザーリクエスト | UXに優れたシンプルなECサイトの新規構築（デジタル商品販売） |
| リクエスト種別 | 新規プロジェクト（グリーンフィールド） |
| スコープ見積もり | システム全体（フロントエンド・バックエンド・管理画面・決済） |
| 複雑度見積もり | 中程度（デジタル商品特有の考慮事項あり、ただし在庫・配送は不要） |
| 優先方針 | UX優先・購入導線の最短化・モバイルファースト |

---

## 採用した改善方針（AIによる判断）

ユーザーより改善点の判断を一任された。以下の方針を採用する。

| 項目 | 元の回答 | 採用方針 | 理由 |
|---|---|---|---|
| 顧客管理の定義 | ゲスト購入のみ + 顧客管理（矛盾） | ゲスト購入ベース＋購入後に任意アカウント作成を提案 | UXを損なわずリピーター獲得の余地を残す |
| セキュリティ拡張 | スキップ | **有効化** | 決済・個人情報を扱うECサイトは本番前提ならセキュリティ必須 |
| 購入導線 | 最短化（定義なし） | 商品ページ→決済入力→完了の2ステップ | デジタル商品は即時提供できるためカートページを省略可能 |

## 機能要件

### FR-01: 商品カタログ
- デジタル商品（ダウンロード・ライセンス等）の商品一覧を表示する
- 商品詳細ページ（タイトル、説明、価格、サムネイル、プレビュー）を表示する
- カテゴリ・タグによる商品の絞り込み検索ができる
- 商品一覧はモバイルファーストのグリッドレイアウトで表示する

### FR-02: 購入フロー（2ステップ方式）
- **ステップ1**: 商品ページから直接「購入する」ボタンで決済画面へ遷移する
- **ステップ2**: 決済情報（メールアドレス、カード情報）を入力して購入完了
- カートページは省略し、複数商品を購入したい場合は都度購入とする（シンプル化）
- 購入完了後、ダウンロードリンクまたはライセンスキーをメールで自動送信する

### FR-03: ゲスト購入 & 任意アカウント登録
- アカウント登録なしでゲスト購入できる（メールアドレスのみ必須）
- 購入完了画面で「アカウントを作成して購入履歴を管理する」を任意で提案する
- アカウント作成後は過去の購入履歴・ダウンロード履歴を参照できる

### FR-04: 決済
- Stripe を利用したクレジット/デビットカード決済に対応する
- 決済失敗時はエラーメッセージを表示し、再入力を促す
- 購入完了後に領収書メールを自動送信する
- デジタル商品のチャージバック不正対策として、ダウンロード前にStripeの決済確認ステータスを必ずチェックする

### FR-05: デジタルコンテンツ配信
- 購入後のダウンロードリンクは署名付き一時URL（有効期限付き）で発行する
- ダウンロード回数制限を商品ごとに設定できる（デフォルト: 5回）
- ライセンスキー配布型の場合は、購入1件に対し1キーを自動割り当てる

### FR-06: ユーザーアカウント（任意登録）
- メールアドレス＋パスワードでアカウント登録・ログインができる
- マイページで購入履歴・ダウンロード履歴を確認できる
- パスワードリセット（メール送信）機能を持つ

### FR-07: 管理画面（バックオフィス）
- **商品管理**: 商品の登録・編集・削除・公開/非公開の切り替え
- **注文管理**: 注文一覧の確認、注文詳細（購入者メール・商品・金額・日時）の参照
- **顧客管理**: 注文と紐付いたメールアドレス・氏名の一覧確認（ゲスト注文を含む）
- 管理画面へのアクセスは管理者アカウントのみに制限する

## 非機能要件

### NFR-01: UX・アクセシビリティ
- 購入完了まで最大2ステップ（商品ページ→決済→完了）を厳守する
- モバイルファースト設計とし、スマートフォンで快適に操作できる
- ページ読み込み時間は3秒以内（Core Web Vitals 基準）
- WCAG 2.1 AA レベルのアクセシビリティに準拠する

### NFR-02: セキュリティ（有効化）
- 決済処理はすべてStripe側で処理し、カード情報をサーバーに保存しない（PCI DSS準拠）
- HTTPS必須（TLS 1.2以上）
- OWASP Top 10 への対策を実装する（SQLインジェクション、XSS、CSRF等）
- 署名付きURLによるダウンロードリンクの保護（未購入者からのアクセス遮断）
- 管理画面は強固な認証（パスワード＋多要素認証推奨）で保護する
- 個人情報（メールアドレス、氏名）は暗号化して保存する

### NFR-03: パフォーマンス・スケーラビリティ
- 月間アクティブユーザー〜1,000人規模を対象とするが、将来的な拡張を考慮した設計とする
- 静的コンテンツはCDN配信でグローバルな高速化を図る

### NFR-04: 保守性
- 日本語・日本円のみ対応（多言語・多通貨は将来拡張として設計上考慮）
- コードは TypeScript で統一し、型安全性を確保する

## 技術スタック（推奨構成）

| レイヤー | 技術 | 選定理由 |
|---|---|---|
| フロントエンド | Next.js (App Router) + TypeScript | SEO対応・SSR/SSG・モバイルファースト |
| スタイリング | Tailwind CSS | レスポンシブ対応が容易・シンプルなUI構築に最適 |
| 決済 | Stripe | デジタル商品対応・不正検知・PCI DSS準拠 |
| バックエンド | Next.js API Routes（または AWS Lambda） | シンプルな構成で管理コスト低 |
| データベース | PostgreSQL（AWS RDS または Supabase） | リレーショナルデータに適切 |
| ファイルストレージ | AWS S3 + CloudFront（署名付きURL） | デジタルコンテンツの安全な配信 |
| 認証 | NextAuth.js | メール/パスワード認証、拡張性あり |
| メール送信 | Amazon SES または Resend | 購入完了・ダウンロードリンク通知 |
| ホスティング | Vercel（フロントエンド）+ AWS（バックエンド） | Next.jsとの親和性が高い |
